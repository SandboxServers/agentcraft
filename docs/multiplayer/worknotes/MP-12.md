## APIs and implementation details for later packets

- **`dev.mp.send`** takes one flat request:
  `{payload:"public_state", state:{…}}`, `{payload:"studio_event", event:{…}}`,
  `{payload:"world_intent", intent:{…}}` or `{payload:"hello", protocol, modVersion}`.
  It parses through `PublicJson` (`fromJson` / `eventFromJson` / `intentFromJson`) and then sends the
  record with `ClientPlayNetworking.send`, so the registered codec is the wire path. A malformed request
  is refused before the send with the codec's own `PublicJson` message. The reply is `{type, sent:true}`.
  It needs a **remote** server (`mc.getSingleplayerServer() == null`; singleplayer is refused first,
  before `canSend`, with `dev.mp.send needs a remote server; singleplayer takes no multiplayer path`),
  `mc.getConnection() != null` and `ClientPlayNetworking.canSend(type)`. The C2S receivers do not
  exist until MP-06 (`PublicStateC2S`, `StudioEventC2S`) and MP-07 (`WorldIntentC2S`) register them; until
  then the server has no handler for those three, and the command is meant for those packets' and MP-I's
  tests. `hello` is already handled by MP-F.
- **`dev.mp.relay`** returns MP-F's `MpDevFake.studios()` shape plus `events`:
  `{mode, studios:[…], events:[{<public event JSON>, studio:"<uuid>"}]}`. The ring keeps the last 32
  received events (relayed and `dev.mp.fake`-injected), guarded by a lock; it is read on the client thread
  and never written to a log. It is cleared when `MpMode` drops to `SINGLEPLAYER` (leaving a server), so it
  holds one server's events per connection, not per JVM. There is no new file and no new network surface.
- **`dev.state`** now carries `mode` (`MpMode.current().name()`), `studios` (the same array as
  `dev.mp.studios`) and `plot` (`{index,x,y,z}` or `null`, read from `Studios.plot(Anchors.self())` and
  nowhere else). `world.name` is still `null` on a remote server, so MP-H's
  `isRemoteReady` keeps working. The own plot comes from the server's hello — MP-F's `MpMode.receiveHello`
  calls `Studios.setPlot` with `HelloS2C.plotIndex`, which carries MP-03's allocation — so `plot` is
  `null` in singleplayer (no hello arrives) and on a remote server until the server has allocated one.
  There is no `Plots.directory()` fallback: on a client that seam is always `Plots.SINGLEPLAYER`.
- **Remote commands** (`dev.command`, `dev.time`, `dev.weather`): the same text is sent to the server as
  the player would type it, after `DevCommands.remoteCommandText` strips one leading `/` and refuses a
  blank, over-256-character or non-chat `cmd` (a `DevException` naming `cmd`; the server would disconnect
  the client for the last one). The reply is `{cmd, sent:true}` with the text actually sent; the
  integrated path is unchanged.
- **Studio tokens:** `MpDevCommands.resolveStudio(String)` is public: absent, blank or `"own"` (any case)
  is `Anchors.self()`; anything else must be a UUID string, as `dev.mp.studios` prints it. A bad token is
  a `DevException`. `dev.camera`, `dev.anchors`, `dev.hq.check` and the `studio` field of a `dev.play`
  camera JSON all use it.
- **Remote camera:** the player's position and game mode belong to the server, so the command sends
  `/gamemode <mode>` when the request is not `keep`, then `/tp @s x feetY z yaw pitch`, and waits for the
  position (and spectator flag) before pinning and running the unchanged `cameraMatches`. It needs op;
  the timeout error says exactly: `the server did not move the player within 10 s: the remote /tp needs
  op (the harness opps its players); see chat`. The five numbers go through `tpArg`,
  `BigDecimal.valueOf(d).toPlainString()` (the `BigDecimal(double)` constructor would print 64.38 as
  `64.3799999999999954525…`), because Brigadier's double reader refuses `1.0E7`. `mode:"creative"` cannot
  turn on flight without a vanilla command, so exact-pose shots should use the default `spectator`.
- **`A20` evidence:** the three `needServer` sites (`dev.camera`, `dev.release`/`dev.command` and
  `dev.quit`'s world save) are the ones audited; `dev.time`/`dev.weather` reuse `serverCommand`. The
  integrated-server paths are byte-for-byte the same code, now behind `integratedServerCommand`.

## Deviations and open risks

- **`dev.mp.send` is a deliberate dev-only publisher.** It can state any `PublicPolicy` in the state it
  builds, because the server trusts the publisher's declared policy (MP-05/MP-06). It is not a new
  boundary: it is registered only on the loopback DevBridge (which already refuses browser origins), it
  builds only through the frozen `PublicJson`/codecs, and the authority boundary stays MP-06/MP-07. It
  cannot send anything but the four C2S types and only when the server advertises them.
- **Remote `dev.camera` needs op.** The harness opps its players; any other caller must be op or the
  command times out with the op-specific message. `mode:"creative"` cannot enable flight (there is no
  command for it), so use the default `spectator`.
- **`dev.mp.send` for `public_state`/`studio_event`/`world_intent` has no receiver yet.** Those commands
  are for MP-06/MP-07 and MP-I; until those merge, only `hello` is handled on the server.
- **`dev.mp.relay` includes locally injected fake events**, because they use the same `Studios.fireEvent`
  path as relayed ones. The event is tagged with its studio id; the ring is bounded, never logged, and
  cleared when `MpMode` drops to `SINGLEPLAYER`.
- **`plot` in `dev.state` is `null` in singleplayer and until the server's hello carries an allocated
  plot** (MP-03); it is read from `Studios.plot(Anchors.self())` only, with no `Plots.directory()`
  fallback, so no client-only registry value can invent a plot.
- **`dev.mp.send` refuses in singleplayer.** The integrated server does register the hello receiver, so
  without the guard a request would be built and sent over the loopback; `send` now throws before
  `canSend` (`dev.mp.send needs a remote server; singleplayer takes no multiplayer path`). Not gated on
  `MpMode`: re-sending `hello` from `REMOTE_VANILLA` stays a legitimate test.
- **`dev.hq.check`'s `minLight` is now an integer 0..15** (`Fields.optInt("minLight", 7, 0, 15)`);
  before, `req.get("minLight").getAsInt()` read any JSON number and coerced strings, so `minLight: 20`
  and `minLight: "7"` used to work and are refused now. Light really is 0..15, but this is a
  singleplayer-visible tightening the packet did not ask for; kept, per review.
- **No game test and no telemetry:** client-only dev code with no server-observable behaviour and no new
  event; both were checked against MP-F's rules rather than invented.
- **Foreman/tools suites:** `npm test --prefix tools` is 61/61; the Foreman suite was not touched and is
  not required (the packet did not edit `foreman/` or `tools/`).
