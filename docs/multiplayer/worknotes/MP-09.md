## What shipped

The own studio renders exactly as before. A display whose panel resolves through
`Studios.at(pos)` to a **remote** studio renders from `PublicStudioState` only; an empty resolution or
`own()` keeps today's `ForemanState` path.

| Files | Behavior |

No Minecraft, no `ForemanState`, no log. `NO_STUDIO` for a null state, `NO_AGENT` for a binding the state does not hold. |

## Why this is the privacy boundary

- The remote renderers read `StudioView.publicState()` and nothing else. `RemoteMonitorView` and
  `RemoteBoardView` have no component a private record can satisfy, and a JUnit test asserts that.
- Opt-in text is structural: `PublicStudioState` already refuses an activity, goal text or task list
  while its policy flag is off, so a view built from it cannot hold text the owner did not opt in.
- A missing state is `NO_STUDIO`/not-present, never a fallback to the viewer's own Foreman.
- `activity` stays null through the view; the screen prints the literal "activity hidden".

## API notes for another packet

- `StudioDisplays.at(BlockPos): Optional<StudioView>` in `client/monitor` is public and cached. Any
  renderer that resolves a panel's studio can use it; install with `StudioDisplays.init()` (idempotent).
  It is only valid on the client thread.
- `RemoteMonitorView.of(@Nullable PublicStudioState, boolean online, String binding)` and
  `RemoteBoardView.of(@Nullable PublicStudioState, boolean online)` are the pure models. Both carry the
  state's `rev`; a caller that wants a cheap "did this change" check can compare the records.
- The remote board reuses `TaskBoard`'s package-private `Column`, `Col`, `Title`, `seq` and the
  density/geometry constants. A later packet that changes those shapes must keep the remote board's
  assumptions (four lanes, `Column.count`/`blocked`, `Title.wrap`).
- `DisplayText.ACTIVITY_HIDDEN` and `DisplayText.WAITING_STUDIO` are the shared remote wording; MP-10's
  stations can reuse them.

## Decisions, as implemented

- **Four lanes; blocked in Todo.** `RemoteBoardView` maps `TaskStatusWire.BLOCKED` to `Lane.TODO` and
  carries `Counts.blocked()` on the Todo column, drawn as the red "N blocked" text. Todo's own count is
  `Counts.todo()`; blocked is a separate count, so the lane's visible blocked cards are not added to it.
  This is the one judgement call: the record gives `todo` and `blocked` as separate statuses, and the
  packet says "counts per status from `Counts`", so each lane takes its own status count and blocked is
  the red subset.
- **`foremanRevision`.** The shared base read stays. Neither remote renderer reads or keys on
  `foremanRevision`; both key on the remote state's `rev` (the view record's first component).
- **`Studios.at` empty while in multiplayer** takes today's own path, exactly as the renderer rule says;
  the pre-layout window is MP-I's to check.

## Deviations and open risks

- **The remote look is unverified on screen.** This sandbox cannot start a client; the exact commands
  for the coordinator are below. The pure models, the cache keys and the source isolation are unit-tested;
  the actual pixels (badge legibility, card fit, offline dim) were not observed.
- **The Todo count excludes blocked.** See "Decisions, as implemented". If the coordinator wants the own
  wall's exact rule (`count` includes blocked), it is a one-line change in `RemoteBoardView.of`.
- **The remote wall is not animated.** Cards are plain, no phase/assignee, per "titles only". This is
  intentional and cheaper than the own board.
- **Under the singleplayer overlay the block states stay the viewer's own** (the singleplayer driver is
  still running). Only the text and the counts come from the injected state, which is what the shots
  check. On a dedicated server the intent applier is the only writer (MP-07), and MP-10 records the same
  caveat.
- **`Studios.at` empty before a layout arrives** renders the viewer's own state on a foreign display
  (correctness, not a cross-player leak): the frozen rule, and MP-I's check.
- **A stale own `TaskBoard` could outlive a panel turning remote.** The click and block-outline paths
  now consult `StudioDisplays.at` and refuse a remote panel, so the viewer's `TaskScreen` cannot open on
  it; the own board entry is only evicted by the 30 s idle sweep.
