## What shipped

The client turns the local Foreman model into `PublicStudioState` and `StudioEventC2S` and sends them only while `MpMode` is `MULTIPLAYER`. Singleplayer does not send and does not log `public_state_sent` or `public_state_skipped`. The publisher never writes the projection into `Studios`.

| File | Behavior |
|---|---|
| `client/mp/publish/Redactor.java` | Pure `ForemanState` + `PublicPolicy` → `PublicStudioState` with `rev` 0. Opt-in text only when that flag is on; a blank opt-in value is null. Strings are cut to the codec cap and passed through `MpText.sanitize`. `UNKNOWN` agent state → `idle`, station → `desk`, goal → `none` (progress 0, no text). An `UNKNOWN` task is left out of `tasks` and out of `counts`. CI is slot indexes `0..7` only. `awaitingUser` is `AgentManager.owner` on each open decision. `foremanOnline` is `link().synced()`. |
| `client/mp/publish/PublishScheduler.java`, `SendWindow.java` | Coalesces state to the latest projection and sends at most `publicStatePerSecond` times in any one-second window. A limited state stays dirty. Events use a separate one-second window; an event first causes a dirty state to be attempted, then is held in an at-most-rate FIFO while that state remains dirty. Held events follow the next state and precede newer events; events over the limit are dropped. A changed rate and `reconnect()` clear both windows; reconnect also clears held events and forces a fresh state. |
| `client/mp/publish/PolicyStore.java` | Four flags, all false when the file is missing or malformed. Written only when a flag changes, to `<gameDir>/config/agentcraft-public.json`. Bits: `activityText=1`, `sayText=2`, `taskTitles=4`, `goalText=8`. |
| `client/mp/publish/PublishGate.java` | `SINGLEPLAYER` is quiet even when the play channel is sendable. `REMOTE_VANILLA` is refused. `MULTIPLAYER` sends only when both C2S channels can send. |
| `client/mp/publish/PublishFeature.java` | Wires the Foreman listener, client tick, mode listener, and `/agentcraft-public`. Viewing works in every mode; flags can be changed only in `MULTIPLAYER`. Singleplayer is silent and does not create a policy file. Production supplies the command mode and caller identity through testable seams. |
| `mod/src/test/java/dev/agentcraft/mp/publish/*` | Marker-based leak scan including encoded packets and a clipped-prefix regression; redaction edge cases; real tick, command, listener, rate-window and event-ordering behavior; policy persistence; whole-line telemetry captures. |

`/agentcraft-public` prints the four booleans in every mode. `/agentcraft-public <flag>` toggles and `/agentcraft-public <flag> <true|false>` sets only in `MULTIPLAYER`. In other modes a set/toggle leaves the policy and file unchanged and prints the current booleans followed by: `Flags can be changed while connected to an AgentCraft multiplayer server.`

## APIs and implementation details for later packets

- `Redactor.redact(ForemanState, PublicPolicy)` returns a state whose `rev` is 0. `PublishScheduler` stamps `rev` when it sends, starting at 1 for each transition to `MULTIPLAYER`. Do not compare revs. The latest state wins. A task title that is blank after clipping and sanitizing is omitted from `tasks`; its count is unchanged, and no replacement title is invented.
- `Redactor.say(ForemanState, AgentSay, PublicPolicy)` sets `Say.text` only when `sayText` is on, after the 120-character clip. `Say.length` is the original length either way. `Say.to` is kept only for `user`, `all`, or an agent id that was published. Any other addressee, including a path, becomes null. A say whose agent is not in the published set is not sent.
- `Redactor.taskDone(ForemanState, previous, now)` matches the own-studio rule: the transition into `DONE` with an assignee who is a published agent. A snapshot does not replay historical dones or `lastSay`.
- `counts.openDecisions` is every open decision, merges included. `counts.openMerges` is the merge subset. `CANCELLED` tasks are listed when `taskTitles` is on and are in none of the five status counts.
- The first 16 agents, first 32 tasks with a known status and nonblank sanitized title, and first 8 repos are kept, in Foreman map order. A second agent whose id clips to one already kept is dropped, so the codec's duplicate-id refusal cannot disconnect the owner.
- `PublishScheduler` reads the rate from the caller on each flush/offer. Production passes `MpMode.serverInfo().publicStatePerSecond()`, or 0 when that optional is empty, which skips with `not_multiplayer`. Client state and events use separate sliding windows and send at most the configured rate in any one-second window; unlike the server `RateBucket`, there is no double-sized initial burst. A rate change or reconnect starts both windows empty. A dirty state is attempted before an event; if state is still rate-limited, the event enters the FIFO (capacity = rate), and after state succeeds held events are processed oldest first through the event window.
- Telemetry, all via `MpLog.event(MpEvents.…)`:
  - `public_state_sent` (debug): `player`, `studio`, `plot`, `rev`, `agents`, `bytes`, `policy`. `bytes` is the UTF-8 length of `PublicJson.toJson(state).toString()`. `plot` is `Studios.plot(Anchors.self())`, or `-1` when the player has none. MP-06 still refuses `no_plot`.
  - `public_state_skipped` (debug): the same correlators (`rev` is the last sent rev, 0 if none) and `reason` one of `MpReasons.UNCHANGED`, `RATE_LIMITED`, `NOT_MULTIPLAYER`. Each skip category logs once per streak, including repeated zero-rate offers/flushes.
  - `policy_changed` (info): `player`, `studio`, `before`, `after`. No plot, rev, path, or flag text.
- The sink builds `PublicStateC2S` / `StudioEventC2S` and sends them with `ClientPlayNetworking.send` only when the mode is `MULTIPLAYER`, the client player and connection exist, and `canSend` is true for that payload. `canSend(Type)` returns false when there is no connection; `send` throws `IllegalStateException` ("Cannot send packets when not in game!") in that case, so the tick returns first.
- MP-06 still owns relay attribution. This payload has no studio field. Clear `Say.text` again on relay when the stored policy's `sayText` is off: an event carries no policy of its own. The publisher withholds the text twice, when the event is made (`Redactor.say`) and again at the moment it is sent (`PublishScheduler`), so a say that was held behind a state loses its text if the owner switched `sayText` off in between.

## Deviations and open risks

- A policy change is refused outside `MULTIPLAYER`: no file write, telemetry or scheduler dirtiness. A view command still works in every mode. Tick behavior is covered through the scheduler/tick seams; no client was launched by this worker.
- `Say.to` is narrowed as above. The Decisions do not mention `to`. Sending an arbitrary addressee would let a path leave the machine.
- A task-done or say for an agent who was dropped by the 16-agent cap is not sent.
- `Say.length` still reveals the original length while the text is null. That is the Decisions rule.
- Client state and event rates follow the contract's strict sliding window; the server's `RateBucket` remains unchanged and has its separate jitter tolerance.
- The offline-link test calls package-private `ForemanState.setLink` by reflection. `ForemanState` is outside this row, and `ForemanStates.fromSnapshot` always builds a synced link.
- No live client was started. Nothing in the HQ, the renderers, or the agent entities was edited, so there is no singleplayer QA compare for this packet. The coordinator runs the chat and dedicated-server checks below.
- A player with `plotIndex == -1` still sends. Refusal is MP-06's `no_plot`.
