## What shipped

The client turns the local Foreman model into `PublicStudioState` and `StudioEventC2S` and sends them only while `MpMode` is `MULTIPLAYER`. Singleplayer does not send and does not log `public_state_sent` or `public_state_skipped`. The publisher never writes the projection into `Studios`.

| File | Behavior |
|---|---|
| `client/mp/publish/Redactor.java` | Pure `ForemanState` + `PublicPolicy` → `PublicStudioState` with `rev` 0. Opt-in text only when that flag is on; a blank opt-in value is null. Strings are cut to the codec cap and passed through `MpText.sanitize`. An agent whose cut and sanitized id is not an identifier path is left out, and a skin that is not one becomes the agent's id. `UNKNOWN` agent state → `idle`, station → `desk`, goal → `none` (progress 0, no text). An `UNKNOWN` task is left out of `tasks` and out of `counts`. CI is slot indexes `0..7` only. `awaitingUser` is `AgentManager.owner` on each open decision. `foremanOnline` is `link().synced()`. |
| `client/mp/publish/PublishScheduler.java`, `SendWindow.java` | Coalesces state to the latest projection and sends at most `publicStatePerSecond` times in any one-second window. A limited state stays dirty. Events use a separate one-second window; an event first causes a dirty state to be attempted, then is held in an at-most-rate FIFO while that state remains dirty. Held events follow the next state and precede newer events; events over the limit are dropped. A changed rate and `reconnect()` clear both windows; reconnect also clears held events and forces a fresh state. A state that was sent is due again when the own plot becomes known or changes, and when no state went out for `RESEND_NANOS` (20 seconds); see "Pull-request review". |
| `client/mp/publish/PolicyStore.java` | Four flags, all false when the file is missing or malformed. Written only when a flag changes, to `<gameDir>/config/agentcraft-public.json`. Bits: `activityText=1`, `sayText=2`, `taskTitles=4`, `goalText=8`. |
| `client/mp/publish/PublishGate.java` | `SINGLEPLAYER` is quiet even when the play channel is sendable. `REMOTE_VANILLA` is refused. `MULTIPLAYER` sends only when both C2S channels can send. |
| `client/mp/publish/PublishFeature.java` | Wires the Foreman listener, client tick, mode listener, and `/agentcraft-public`. Viewing works in every mode; flags can be changed only in `MULTIPLAYER`. Singleplayer is silent and does not create a policy file. Production supplies the command mode and caller identity through testable seams. |
| `mod/src/test/java/dev/agentcraft/mp/publish/*` | Marker-based leak scan including encoded packets and a clipped-prefix regression; redaction edge cases; real tick, command, listener, rate-window and event-ordering behavior; policy persistence; whole-line telemetry captures. |

`/agentcraft-public` prints the four booleans in every mode. `/agentcraft-public <flag>` toggles and `/agentcraft-public <flag> <true|false>` sets only in `MULTIPLAYER`. In other modes a set/toggle leaves the policy and file unchanged and prints the current booleans followed by: `Flags can be changed while connected to an AgentCraft multiplayer server.`

## APIs and implementation details for later packets

- `Redactor.redact(ForemanState, PublicPolicy)` returns a state whose `rev` is 0. `PublishScheduler` stamps `rev` when it sends, starting at 1 for each transition to `MULTIPLAYER`. Do not compare revs. The latest state wins. A resend carries the next `rev` and the same content. A task title that is blank after clipping and sanitizing is omitted from `tasks`; its count is unchanged, and no replacement title is invented.
- `Redactor.say(ForemanState, AgentSay, PublicPolicy)` sets `Say.text` only when `sayText` is on, after the 120-character clip. `Say.length` is the original length either way. `Say.to` is kept only for `user`, `all`, or an agent id that was published. Any other addressee, including a path, becomes null. A say whose agent is not in the published set is not sent.
- `Redactor.taskDone(ForemanState, previous, now)` matches the own-studio rule: the transition into `DONE` with an assignee who is a published agent. A snapshot does not replay historical dones or `lastSay`.
- `counts.openDecisions` is every open decision, merges included. `counts.openMerges` is the merge subset. `CANCELLED` tasks are listed when `taskTitles` is on and are in none of the five status counts.
- The first 16 agents whose id is an identifier path, first 32 tasks with a known status and nonblank sanitized title, and first 8 repos are kept, in Foreman map order. A second agent whose id cuts or sanitizes to one already kept is dropped, so the codec's duplicate-id refusal cannot disconnect the owner. A second task whose id cuts or sanitizes to one already kept is dropped too; its count is unchanged.
- `PublishScheduler` reads the rate from the caller on each flush/offer. Production passes `MpMode.serverInfo().publicStatePerSecond()`, or 0 when that optional is empty, which skips with `not_multiplayer`. Client state and events use separate sliding windows and send at most the configured rate in any one-second window; unlike the server `RateBucket`, there is no double-sized initial burst. A rate change or reconnect starts both windows empty. A dirty state is attempted before an event; if state is still rate-limited, the event enters the FIFO (capacity = rate), and after state succeeds held events are processed oldest first through the event window.
- Telemetry, all via `MpLog.event(MpEvents.…)`:
  - `public_state_sent` (debug): `player`, `studio`, `plot`, `rev`, `agents`, `bytes`, `policy`. `bytes` is the UTF-8 length of `PublicJson.toJson(state).toString()`. `plot` is `Studios.plot(Anchors.self())`, or `-1` when the player has none. MP-06 still refuses `no_plot`.
  - `public_state_skipped` (debug): the same correlators (`rev` is the last sent rev, 0 if none) and `reason` one of `MpReasons.UNCHANGED`, `RATE_LIMITED`, `NOT_MULTIPLAYER`. Each skip category logs once per streak, including repeated zero-rate offers/flushes.
  - `policy_changed` (info): `player`, `studio`, `before`, `after`. No plot, rev, path, or flag text.
- The sink builds `PublicStateC2S` / `StudioEventC2S` and sends them with `ClientPlayNetworking.send` only when the mode is `MULTIPLAYER`, the client player and connection exist, and `canSend` is true for that payload. `canSend(Type)` returns false when there is no connection; `send` throws `IllegalStateException` ("Cannot send packets when not in game!") in that case, so the tick returns first.
- MP-06 still owns relay attribution. This payload has no studio field. Clear `Say.text` again on relay when the stored policy's `sayText` is off: an event carries no policy of its own. The publisher withholds the text twice, when the event is made (`Redactor.say`) and again at the moment it is sent (`PublishScheduler`), so a say that was held behind a state loses its text if the owner switched `sayText` off in between.

## Pull-request review

**Finding (Medium): a refused state is never sent again.** Valid. `PublishScheduler.sendState` recorded the projection as sent, and `flush` then skipped every equal projection as `unchanged`. The server sends no reply for a refused state (`no_plot`, `rate_limited`, `bad_version`), so with `autoAllocate=false`, a failed allocation, or `plot free` then `plot assign`, the studio stayed empty for other players and its events were refused until the owner's Foreman changed.

**Fix.** `PublishScheduler.resendIfDue` runs at the start of every multiplayer `flush` and `offer`, after the mode and rate gates. It forgets the last sent projection (`last = null`, `dirty = true`), which is what `reconnect()` does for a new connection, in two cases:

1. **The own plot became known or changed.** The scheduler's plot supplier is now `Supplier<Optional<Plot>>`, in production `Studios.plot(Anchors.self())`, polled every flush. A present plot that differs from the one seen at the previous flush (none to some, another index, another origin) makes the state due. Losing the plot sends nothing.
2. **Nothing was sent for `PublishScheduler.RESEND_NANOS` (20 seconds),** measured on the caller's clock from the last state that was sent. An idle client sends three states a minute, and any real send restarts the interval.

There is no second send path. A due state goes through `Redactor.redact` with the policy in force at that moment, then the state window, then `sendState`, so a text switched off since the first send is absent from the resend, and a resend can be rate-limited like any other state. Outside `MULTIPLAYER` the check is not reached: nothing is sent, marked dirty or logged. Events are not replayed.

**What the plot signal sees and misses.** `Studios.plot` for the own studio is written by the hello (`MpMode.receiveHello`) and by MP-04's `LayoutS2C` handler (`Studios.setPlot`), and cleared by `Studios.remove`. On this branch only the hello writes it, and a hello on a new connection already goes through `reconnect()`, so trigger 1 fires in practice only once MP-04's layout sync is merged. It misses a plot the server assigns without telling the client (`plot assign` with no layout published, `autoBuild` off), a free and reassign to the same index between two ticks or that the client was never told about, and every refusal that is not about the plot. Trigger 2 covers those.

**What a viewer sees between a refusal and the next resend.** The studio as the server last stored it: no agents, counts or goal when no state was ever accepted, for at most 20 seconds plus the server's relay. Says and task-dones from that interval are refused by the server (`no_plot`, or `unknown_agent` while it has no stored state) and are lost. After the resend the studio shows the current state, and only later events appear.

**Costs.** MP-06's relay compares content without `rev` (`StudioRelay.sameContent` on its branch; the relay is a stub on this one), so an identical resend is stored and not relayed again. A resend from a player who still has no plot is refused again, three times a minute for each such player. How often the relay logs that refusal is MP-06's choice.

**Wire caps (checked, no code change).** The `Redactor` cannot build a state over the caps. It keeps at most 16 agents (`publicIds`), 32 tasks and 8 CI slots, and clips before sanitizing: agent id, name and skin to 16, activity to 48, task id to 48, title to 80, assignee to a published agent id, goal and say text to 120. The largest possible state, with every character one that JSON escapes to two, is about 16000 characters against the 30000-character envelope (the test's state is 15790; agent ids, skins and assignees are identifier paths, which JSON never escapes). `seventeen_agents_thirty_three_tasks_and_over_long_texts_stay_inside_every_wire_cap` builds that state and round-trips it through `PublicStateC2S.CODEC`.

**Tests added (`PublishSchedulerTest`):** `own_plot_becoming_known_or_moving_sends_the_current_state_again`, `idle_state_is_sent_again_once_per_resend_interval_and_not_before`, `resend_waits_for_the_state_window_and_goes_before_a_later_event`, `resend_shares_only_what_the_policy_shares_when_it_is_sent`, `nothing_is_sent_or_logged_outside_multiplayer_however_much_time_passes`. With `resendIfDue` disabled the first four fail. With the check moved ahead of the mode gate the fifth fails. With a resend that sends the cached state directly, the rate and policy tests fail.

**Finding: an agent id or skin that is not an identifier path.** Valid as a coming failure. The foundation branch now refuses a `PublicAgent` whose `id` or `skin` fails `Identifier.isValidPath` (`[a-z0-9/._-]`), at decode and in the record's constructor, because a viewer's client builds resource identifiers from both. On this branch nothing throws yet, and the `Redactor` published such an agent as it was. After the branches meet, `new PublicAgent(...)` would throw on the client thread.

- **Id.** `Redactor.publicIds` leaves out an agent whose cut and sanitized id is empty or is not an identifier path, with the same effect as the 16-agent cap. Every published agent id comes from that map, so nothing else names the agent: it is absent from `agents`, a task assigned to it is published without an assignee, its say and task-done are not published, and a say addressed to it has `to` null. It does not use one of the 16 places.
- **Skin.** A skin that is empty or not an identifier path after cutting and sanitizing is replaced by the agent's published id. That is the Foreman protocol's own default for a missing skin (`Protocol.Agent`), and the blank-skin rule here already used it. On a viewer's client `AgentSkins` looks for `entity/agent/<skin>.png`: an id that is a cast member's shows that cast skin, and any other id has no texture and gets the vanilla default skin.
- Names are not identifiers and are unchanged. Every agent in both fixture snapshots is published with the same id, name and skin as before.
- Tests (`PublishRedactorTest`): `agent_whose_id_is_not_an_identifier_path_is_left_out_with_everything_that_names_it` ("Wren Smith", "Kit!") fails with the id check removed. `skin_that_is_not_an_identifier_path_becomes_the_agent_id_and_fixture_agents_are_unchanged` ("Wren", "my skin.png") fails with the old blank-only skin rule.

**Finding (automated review): two tasks can be published with the same id.** Valid. With `taskTitles` on, the task loop cut and sanitized the id and checked only that it was not empty, so two ids sharing their first 48 characters, or equal after sanitizing, went out with one id. The codec does not refuse that, so the owner was not disconnected, but a viewer could not tell the tasks apart. Now a task whose public id is already in the list is skipped: the first in Foreman map order keeps the id, and a task skipped for another reason (unknown status, blank title) does not take it. `counts` still includes the skipped task. The agents' rule was already there (`ids.containsValue(id)` on the cut and sanitized id) and tested for the cut; `task_or_agent_whose_public_id_is_already_published_is_left_out` now covers the sanitized case for agents and both cases for tasks. It fails with the task check removed, and it and `caps_drop_the_extra_agent_repo_and_duplicate_clipped_id` fail with the agent check removed.
