## APIs and implementation details for later packets

- The registry is installed only when `server.isDedicatedServer() && MpServerConfig.current().enabled()`, read at call time. `PlotFeature.multiplayer(MinecraftServer)` is that check. On stop, the directory goes back to `Plots.SINGLEPLAYER` without reading `enabled()` again, because the config reset can run first. Singleplayer never allocates, never writes `agentcraft/plots.json`, and never logs `agentcraft.mp` from this packet.
- Allocation runs from `ServerPlayConnectionEvents.INIT` and uses only `handler.getPlayer().getUUID()`. Fabric fires INIT before JOIN, and MP-F sends hello on JOIN, so `MpPayloads.helloFor` already sees the index. There is no payload on INIT. A second allocate of the same studio returns the existing plot and does not log `plot_allocated` again. `StudioId.LOCAL` is refused and not logged. `autoAllocate: false` does nothing.
- The new row is saved during INIT. The build is not. `enqueueBuild` schedules `server.getTickCount() + 2`. `tickCount` increments at the start of `tickServer`, and the end-of-tick handler runs one plot when the tick has reached that value, so the join tick does not build. A spawn queued on JOIN waits while that plot's layout is still empty and a build is pending. `autoBuild: false` does not enqueue.
- Origins come from `PlotGrid.originOf(index, MpServerConfig.current().plotStride())` at call time. The origin is stored in `plots.json`, so a later stride change does not move an existing plot. An origin the grid refuses (`IllegalArgumentException`, including past ±30,000,000) is `plot_allocation_failed` with `reason=grid_full`. At the default stride 128 that refusal is not reachable for any `int` index. At the config maximum 1,048,576 it is.
- `plots.json` is `{"plots":[{"index":0,"owner":"<uuid>","x":0,"y":0,"z":0}]}`. No names and no stride. `y` must be 0, `x` and `z` must be multiples of 16 and within ±30,000,000, the owner must be a UUID and not `LOCAL`, and `index` must be a JSON number (a string such as `"../x"` is skipped). Duplicate index or owner keeps the first row. The skip count is a number on `AgentCraft.LOGGER`, not a new mp event. A missing file is an empty success. Unreadable JSON, a non-object, a missing or non-array `plots`, or a file larger than 1,048,576 bytes loads as failed and **freezes** the registry: later allocate, assign, and free do not replace the file. The same byte cap applies to `anchors.json`; a bad anchors file becomes an empty layout so a rebuild can replace it.
- Writes use a sibling temp file and `Files.move(..., REPLACE_EXISTING, ATOMIC_MOVE)`. On `IOException` the temp is deleted, the previous file stays, and the in-memory row is rolled back. `plot_allocation_failed` then uses `reason=io_error`.
- `PlotFeature.publishBuilt` publishes with `Anchors.publish(studio, layout)` at `forStudio(studio).revision() + 1` and saves that plot's anchors. It does not call `Anchors.publish(server, layout)` and does not move the world spawn. `HqFeature.buildPlot(level, builder, force, origin, studio)` is the public way to build one plot; `HqBuilder.Options` stays package-private. The multiplayer `/agentcraft hq` path uses the source player's plot only. There is no plot argument.
- Respawn is `ServerPlayer.setRespawnPosition(new RespawnConfig(LevelData.RespawnData.of(...), true), false)`. `forced` is true so a non-bed spawn counts. `teleportHome` uses `Entity.absSnapTo` when `connection` is null (game-test mock players) and the eight-argument `teleportTo` otherwise. The three-argument `teleportTo` touches the connection.
- After every successful allocate, assign, or free, `StudioRange.refresh(server)` runs. Listeners are still MP-04 and MP-06.
- `/agentcraft` requires `Commands.LEVEL_ALL`. `hq`, `anchors`, `plot list`, `plot assign`, `plot free`, and `plot rebuild <index>` require `Commands.LEVEL_GAMEMASTERS`. `plot info`, `plot home`, and `plot rebuild` without an index do not. Child requirements are checked again inside the executor, so a test can call the method directly. The acting player is `CommandSourceStack.getPlayer()`. Console info and home fail. Console assign and free are allowed because the console source is operator and the target is not an actor.
- `plot rebuild` without an index rebuilds the caller's plot. The index form is ops only, including the owner's own index. `force` is `Options.force`. `plot info` returns `index + 1` so plot 0 is a success. `plot assign <player> <index>` resolves an online player with `PlayerList.getPlayerByName`, or a name already in the profile cache. It does **not** call `UserNameToIdResolver.get(String)`: on a miss that resolves a new offline or network profile. Cache lookup fails closed. An expired cache row is unknown. Assign is refused when the player already has a plot or the index is taken. `plot free <index>` removes the row, deletes only `agentcraft/plots/<index>/`, then `Anchors.remove`. Blocks and `plots.json` stay. A freed owner is allocated again on the next join when `autoAllocate` is on.
- Telemetry, only when the gate is on, and only these events: `plot_allocated` (`player`, `studio`, `plot`, `index`, `origin` as `x,y,z` with no spaces), `plot_allocation_failed` (`reason` is `MpReasons.GRID_FULL` or `MpReasons.IO_ERROR`), `plot_command` (`command` is one of `info`, `home`, `rebuild`, `list`, `assign`, `free`, plus `target_plot` and `ok`). Success and refusal both log when the method runs. A brigadier rejection before the method does not. No player names, paths, or anchor dumps.
- The command root is open, so every later `/agentcraft` subcommand has to set its own permission. This packet gates `hq` and `anchors`. Packets that add a sibling must do the same.
- Game tests install a `PlotRegistry` themselves. The game-test server's `SERVER_STARTED` has already run with `enabled` false, so `PlotFeature` did not install one. Restore config, directory, world spawn, `plots.json`, and any studio anchors before the test returns. Do not `Anchors.remove(StudioId.LOCAL)`.

## Deviations and open risks

- `PlanStore.invalidateUnless(server, builderId)` is still the single world file `agentcraft-hq-plan.dat`. MP-02's per-plot form does not exist on this branch, so the existing call is unchanged. `HqFeature` does not call `Anchors.builder(name).origin`. The builder still ignores `Options.origin` until MP-02. Tests build plot 0 only. **Do not put a second player on a live server from this branch:** `autoBuild` of index 1 or higher would paint the origin site.
- `plot_built` and `plot_build_failed` are not logged. They belong to the builder in MP-02.
- Knowing a cached name without calling `get(String)` uses the private `savedIds` set on the game-test resolver and the private `profilesByName` map on `CachedUserNameToIdResolver`. If those move, lookup fails closed and assign accepts only an online player. Expired rows are treated as unknown and are not refreshed over the network.
- A corrupt or oversized `plots.json` stays on disk until someone replaces it and restarts. The 1,048,576 byte cap is a local safety limit, not a protocol field.
- The two-tick build delay and the hello-before-build ordering were read from `tickServer` and the Fabric join listener. They were not observed on a live join. Game-test persistence is save, drop, and load inside one server, which is what MP-T allows. A second Gradle run would get a new world.
- MP-01 is not on this branch, so `HqWorld.isHq` can still be true in an HQ world. `HqFeature` returns before the legacy auto-build when the multiplayer gate is on, which is the guard this packet can own.
