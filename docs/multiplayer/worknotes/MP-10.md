## API notes for later packets (MP-11, MP-12, MP-I)

- **The seam is `Studios.at(BlockPos)` first.** A station renderer's `extractStation` must resolve it
  before any `Foreman` read; empty or `own()` keeps today's path per the renderer rule. `Studios.at`
  runs on the client thread (`extractStation`), never in `submit`.
- **Pure remote models are public and allocation-light**, so later tests and features can reuse them
  without a client: `DecisionQueue.remote(PublicStudioState)`, `MergeStationRenderer.remoteCard(...)`,
  `MemoryIndex.remoteArchive(...)`, `ConsoleTerminalRenderer.remoteConsole(StudioView)`,
  `StatusLampRenderer.remoteHologram(...)`. Each returns an immutable record and reads only the public
  state/view. `StatusLampRenderer.RemoteHologram` carries a `statusFamily` string, not a colour, so it
  is pure; the renderer maps it through `UiStyle.status`.
- **Remote podium cache** is keyed on `(StudioId, public rev, count)`; it is intentionally **not**
  keyed on `foremanRevision`. The own path keeps its own cache. MP-11/MP-12 must not assume the shared
  `cache` field holds an own card.
- **MP-11 (Visitor interactions):** a remote station's click handling is separate; MP-10 only changes
  what is drawn. The podium deliberately omits the owner's key hint; the console omits the typing
  prompt. MP-11's read-only panel can rely on the station's `Studios.at` result to route.
- **MP-12:** no new DevBridge command. `dev.mp.fake` and `dev.cameras`/`dev.camera` are enough to
  reach every station. `dev.mp.studios` shows the fake view and its `publicState`.
- **MP-I:** on a dedicated server the block states come from the server applier, so a remote lamp's
  colour and a remote podium/merge lit state are the server's. Under the singleplayer overlay they
  stay the viewer's own, because `HqWorldDriver` keeps running (see the caveat below).
- **No migration needed for own studios on a dedicated server:** before a layout or plot is known,
  `Studios.at` is empty and the station keeps the own path (same rule MP-09 follows).

## Deviations and open risks

- **Overlay caveat (settled by the packet's Decisions).** Under `dev.mp.fake {overlay:true}` the lamp,
  podium and merge **block states** stay the viewer's own, because `HqClientFeature` still runs
  `HqWorldDriver.tick` from the singleplayer state. The remote look is verified by its **text and
  holograms** (counts, labels, status, progress), which all come from the fake public state. On a
  dedicated server the server applier is the only writer, so the block states are the studio's own.
- **Remote lamp colour is the block state, not the public state.** Deriving it from `PublicStudioState`
  would duplicate MP-07's binding→lamp mapping; the packet's Decisions chose the server block state.
- **Podium face uses the public agent `id`, not `skin`.** The pure model carries `id`/`name`; the
  portrait path and the `Cast.get(...)` guard are exactly the own ones. A remote agent id that is not
  in the cast shows its public name with no face. MP-08 owns the agent-skin rendering for remote
  agents; if a later packet needs a distinct skin, the `PublicAgent.skin` field is on the wire already.
- **Remote hologram decisions line.** A remote studio's decisions wait for its owner, so the count
  line reads "N decision waiting" / "N decisions waiting", never "need you".
- **`HqClientFeature` near-plot scan cost.** `scan` runs every 20 client ticks and walks each studio's
  layout bounds; unloaded chunks are skipped. It allocates one small `HashSet<Long>` per scan (not per
  frame), which is within the advisor's "no per-frame allocation" rule.
- **One failed first attempt, no source change:** the first `gw build -x runGameTest` compiled and ran
  the tests green; the red run then replaced the test-result directory with a single failing test, so
  the totals above were taken after re-running `gw test --rerun --no-build-cache`.
