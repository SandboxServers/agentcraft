## APIs and implementation details for later packets

- `Studios.all()` is reconciled on the client tick. A studio receives its entity-id base only when its
  `StudioAgents` attaches: slot 0 starts at `-10000`, slot 1 at `-11000`, and each allocator stops
  before the next studio's base. Released ids are reused within that window. The pool is reset when
  the client level changes; foundation slots themselves are not reused before `Studios.reset()`.
- The own-studio spawn fallback is singleplayer only: `StudioAgents.shouldRunOwnAgents(mode, layout)`
  is false for `MpMode.MULTIPLAYER` with an empty layout, and `useSpawnFallback` is true only when the
  mode is not multiplayer and the layout is empty. A waiting agent near the player keeps the base
  anchor name `user@player`; a remote waiter uses `user@owner`. `logAttached` / `logDetached` are the
  telemetry writers (`MpLog.event`); the test captures those lines.
- `AgentManager.entities()` and `entity(String)` intentionally remain own-studio-only for
  `AgentCardScreen`. `entity(StudioId,String)`, `allEntities()`, `byEntityId`, `settle()` and
  `movingCount()` cover attached studios. The existing `dev.agents` response now includes `studio`
  and `slot` for each entry; its `id` remains the cast id and `entityId` is the actual negative id.
- Remote station placement uses `StationAssigner.assignPublic(List<PublicAgent>, Layout)`; it does not
  construct a `Protocol.Agent`. Chair fallback takes an explicit `Layout` via the new `Seats.at`
  overload. Existing callers of the old `Seats.at` overload still use `Anchors.current()`.
- `AgentView.id` is still the cast id used by anchors, cast colors and skins. `AgentView.plateKey` is
  the owner-UUID-qualified key passed to `AgentRenderer` and used by `PlateLayout`.
- `PublicEvent.Say` is consumed by the remote studio only. A null text becomes `…`; timing uses the
  public `length`, not the ellipsis's one character. `to="user"` is labeled with that studio's owner
  name (fallback `owner`); agent addressees resolve from the current public agent list.
- `RemoteAgentClicks.fire(StudioView,String)` is called for remote clicks. Until MP-11 registers its
  handler, these clicks do nothing. The own card remains unchanged.
- Minecraft 26.3 signatures used by this packet were checked against the read-only 26.3 sources in
  `<repo>/mod/build/mcsrc`: `ClientLevel.players()`, `addEntity(Entity)`,
  `removeEntity(int, RemovalReason)`, `Entity.setId(int)`, `getUUID()`, `isSpectator()`,
  `getX()`, `getY()`, `getZ()`, `getEyePosition()`, `BlockPos.containing(double,double,double)`,
  and the client executor's `isSameThread()` / `execute(Runnable)`. The source confirms that
  `ClientLevel.addEntity` removes any existing entity at the supplied id first, so distinct studio
  windows are required.

  12-agent measurement are unverified; run the exact checks above and inspect the PNGs before making
  a visual claim. No QA run id is available yet.
- No game tests were added because the packet tests client-only agents; the work-packets test list
  calls for JUnit and live DevBridge/screenshots, not a game test. There is no valid headless-client
  path in MP-T's shared server environment.
- MP-08 verifies the fake remote view without the MP-04/MP-06 network path. Real remote layouts,
  state relay, presence and owner-player lookup still need integration verification after those
  packets land.
- The owner-follow path requires that the owner's player entity be loaded and be inside the plot.
  When it is not, agents use the remote layout's podium/user anchors; they never use the viewer as a
  fallback target.
- `AgentView.id` remains the cast id; consumers that need a plate identity must use `plateKey`.
  `PlateLayout` still exposes its existing string-based lookup, now with the qualified key.
